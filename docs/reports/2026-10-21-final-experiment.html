Graph-derived repository QA benchmark · final experiment, 17–21 October 2026

Repo-QA Final Experiment

11 open models answered the same 250 questions about 10 Python repositories, once with read-only access to the code and once without. Every gold answer comes from a Cypher query over a static code graph. With the code, scores range from 0.14 to 0.87. Without it, every model lands between 0.17 and 0.26.

Excluded models

Excluded

deepseek-r1:32b answered in prose instead of calling a tool. Every condition, closed-book included, submits through a tool, so it cannot be scored. Ollama lists tool support for it.

Excluded

qwen2.5-coder:32b wrote its tool call as text, {"name": "submit_answer", "arguments": {"answer": 42}}, which Ollama does not parse into a call. Accepting text calls for one model would change the harness after eleven others ran, so it is excluded rather than special-cased.

Scored

nemotron3:33b is scored but its result is mostly tool-format failure. It wrote XML tool calls that Ollama often could not parse: 1640 malformed calls, and no answer on 96 of 250 questions. Its 0.44 measures the model and the server's parser together.

How it was run

  • Questions. 477 generated from code graphs of 10 repositories (83% hard), rewritten into natural developer wording by an agentic naturaliser with repository access that never sees the answer, then checked by a resolver and a judge; 434 rewrites accepted, the rest keep template wording. A fixed sample of 250, proportional by repository, family and template, was evaluated (data/questions_v4_eval/manifest.json).
  • Harness. The same read-only tool loop for every model: list_dir, read_file, grep, and a typed submit_answer. Budget of 30 steps; on the last step only the submit tool is offered. Closed-book runs get no repository tools.
  • Hardware. One NVIDIA A100 40 GB, Ollama 0.40.5, every model at 4-bit, 64K context (qwen3:8b capped at its native 40K). Each model got as many parallel slots, up to 4, as kept it entirely on the GPU; architectures Ollama cannot batch ran one question at a time.
  • Scoring. Exact match for yes/no, counts and names; F1 for lists; any valid call chain of the right length for shortest-path questions. The first finished attempt at each question counts; only infrastructure outages are retried.

Corrections and caveats

Everything below was found during or after the run. Predictions were stored, so every correction is applied by re-scoring, without re-running a model; both versions are reported.

  • Gold answers (3 changed). A call through a renamed import, from .joiner import cli as remote_cli, was resolved by pyan but rejected by the call-site check, which saw remote_cli, not cli. Fixed and re-extracted: 206 call edges restored across the 10 graphs.
  • Answer forms (v2). Accepted as correct: Class.method where the question asks for the class; file paths with a note appended; the importable name in a src/ layout; and C.__init__ for a class with no explicit __init__.
  • Retries. A resume used to re-run questions a model had failed to answer, keeping the latest attempt. Now only outages are retried and the first finished attempt counts. This moved nemotron3 from 0.49 to 0.44 and gpt-oss by −0.006.
  • Malformed tool calls that the server rejects (HTTP 500) are now counted against the model inside the run, as invalid JSON already was. The 15 questions run under the old handling were re-run.
  • Rewriting model. qwen3.8:27b rewrote the questions and is also scored. It never saw the answers, but a home advantage in wording cannot be ruled out.
  • Timing. qwen3.8's first six repositories ran four questions against one slot, so their per-question times include queueing. Scores, steps and tokens are unaffected.
  • Context. 8 of 2,750 repo-access runs passed 60K tokens and may have lost early context; they are almost all failures anyway, and none changes a ranking.
  • Sample size. 250 questions give each model a standard error of about 0.02–0.03. Adjacent models closer than about 0.05 (gpt-oss and muse-glimmer, for one) are not separated.

Next steps

  1. Manually verify a sample per family against the source code, to put a number on gold-answer accuracy beyond the fixes above.
  2. Frontier models through the API, on the same 250 questions: about $20–90 per model at list prices, less with prompt caching.
  3. Larger open models (gpt-oss:120b, nemotron-3.5-super) need an 80 GB GPU.
  4. Commit the code, question sets and results, which are not yet in git.
