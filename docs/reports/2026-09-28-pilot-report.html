How a question is made now

Extract

pyan3 and an AST pass build the CodexGraph schema plus a CALLS edge, loaded into Neo4j.

Generate

Templates sample entities; the stored answer is whatever the template's Cypher returns.

Filter

Drop a question if a call static analysis could not resolve could change its answer.

Balance

Every yes/no template gets both answers in equal measure, with hard "yes" cases.

Rewrite

A writer with repo access rephrases it; a resolver and a judge must confirm the same entities and the same answer.

Evaluate

Each model answers with repo access and closed-book, through one identical agent loop.

Templated

Does the class agentic.tools.web_search.scrape.LLMExtractionOptions define an attribute named chunk_overlap_chars?

Rewritten

Does LLMExtractionOptions in agentic/tools/web_search/scrape.py define an attribute named chunk_overlap_chars?

Ground truth for both
MATCH (c:CLASS {repo_id: $repo, qname: $class})
RETURN exists(
  (c)-[:HAS_FIELD]->(:FIELD {name: $field})
) AS has_field

The rewrite changes the wording, never the query. Two pilots in a row showed zero accuracy flips between the two wordings.

    Open issues

    High

    The two models tested do not separate. Fifty questions, half of them lookups at ceiling, cannot tell 0.83 from 0.86 apart. The hard half needs a larger sample of its own.

    High

    The time limit penalises slow models. Five minutes per question suited stalled API calls, but on local hardware it cut qwen3.5-27b off on 11 of 50 questions. The 30-step cap should be the budget instead.

    Medium

    Yes/no questions still leak a prior. Closed-book yes/no scores 0.60 to 0.67 against 0.50 for guessing. "No" pairs usually span unrelated modules, so names alone suggest the answer. Near-miss negatives from the same module would fix this.

    Medium

    Long call-path questions are scarce. The completeness filter keeps only 7 shortest-chain and 4 hop-count questions, because a 6-hop path nearly always crosses an unresolved call. Recovering them needs better call resolution, such as following type annotations.

    Low

    Nothing is manually verified yet, and none of the work is committed to git. OpenRouter's prompt-injection filter also blocked 2 to 5% of API questions on agent repositories; local runs avoid it.

    Next steps, in order

    1. Make the time budget fair for local models, with the step cap as the real limit, and re-run qwen3.5-27b's 11 cut-off questions.
    2. Run a larger sample of hard templates only, about 100 to 150 questions, where all the separation lives. Keep the lookups as a small calibration set.
    3. Add a clearly weak model such as qwen3:8b, to confirm the benchmark spans a range of ability.
    4. Add near-miss negatives to the path yes/no templates.
    5. Improve call resolution to recover long multi-hop questions.
    6. Manually verify a sample per family, then commit.
    7. Scale up: rewrite all questions and run the full model lineup.
